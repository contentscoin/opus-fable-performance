# Verification Grounding

HTML, SVG, UI, 웹페이지, 차트, 게임, 애니메이션, 실행 스크립트처럼 실제 결과를 봐야 맞는지 알 수 있는 산출물에는 이 절차를 적용한다.

## 핵심 원칙

정적 문법 검사는 "파일이 파싱된다"만 확인한다. 화면이 깨지지 않았는지, 버튼이 동작하는지, 차트가 실제로 보이는지, 게임이 시작되는지는 실행하거나 렌더링해야 알 수 있다.

## 절차

1. 자연스러운 실행 환경에서 산출물을 실행한다.
   - 웹/UI: dev server 또는 headless browser.
   - SVG: PNG로 렌더링 후 확인.
   - 스크립트: 실제 실행 후 stdout/stderr 확인.
   - 게임/애니메이션: 초기 상태뿐 아니라 움직임이나 상태 전환까지 확인.
2. 실제 결과를 관찰한다. 생성한 screenshot이나 로그를 다시 읽고, console error를 확인한다.
3. 관찰로 발견한 결함을 수정한다.
4. 수정 후 다시 실행해 같은 결함이 사라졌는지 확인한다.

## 중단 기준

한 번의 깨끗한 실제 관찰이면 충분하다. 변경 없이 같은 검사를 반복해 confidence를 쌓지 않는다. 결함을 고친 뒤에만 재검증한다.
