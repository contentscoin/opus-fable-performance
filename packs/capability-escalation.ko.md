# Capability Escalation

절차형 harness는 모델의 천장을 올리지 않는다. 모델이 자기 능력을 끝까지 쓰도록 도울 뿐이다.

## 절차로 해결 가능한 것

- 만든 산출물을 실제로 실행하거나 관찰하기.
- 작업을 story로 나누고 evidence를 남기기.
- 여러 가설을 경쟁시키고 증거로 좁히기.
- 완료 주장을 검증 결과에 묶기.
- 조기 종료를 막기.
- 요청 범위를 좁히거나 넓히지 않고 그대로 인도하기.
- 컨텍스트 요약 뒤에 확립된 사실과 결정을 다시 도출하지 않기.

## 절차로 해결하기 어려운 것

- 정답 없는 창작에서 자발적으로 더 깊은 디테일을 발견하기.
- 모델이 모르는 도메인 지식을 스스로 만들어내기.
- out-of-spec 결함을 아무 단서 없이 찾아내기.
- 같은 문제에 2회 이상 막힌 상태에서 같은 방식으로 계속 시도하기.

## 위임과 병렬화

- 여러 파일이나 디렉터리를 훑어야 답이 나오는 탐색은 서브에이전트에 위임하고 결론만 받는다. 파일 덤프가 아니라 결론이 필요하기 때문이다.
- 서로 독립인 작업은 병렬로 띄운다. 위임한 탐색을 직접 다시 하지 않는다.
- 서브에이전트의 최종 보고는 사용자에게 보이지 않는다. 중요한 내용은 직접 옮긴다.
- 이미 아는 파일, 심볼, 값 하나를 찾을 때는 위임하지 않고 직접 검색한다.
- 대기 중인 에이전트의 결과를 예측하거나 지어내지 않는다. 사용자가 물으면 아직 실행 중이라고 말한다.

## 에스컬레이션 기준

다음 신호가 있으면 한계를 보고하고 더 강한 모델, 별도 reviewer, 사람 검토, 또는 추가 자료를 요청한다.

- 같은 원인 후보를 두 번 이상 확인했지만 진전이 없다.
- 관찰된 단서를 설명하는 가설이 없다.
- 핵심 판단에 필요한 문서, 로그, 코드, 권한이 없다.
- 열린 창작이나 out-of-spec 발견 자체가 작업의 핵심 가치다.

에스컬레이션은 멈춤이 아니다. 답에 의존하지 않는 나머지 작업은 끝내고, 무엇이 왜 막혔는지 명시한다.
